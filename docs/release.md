# 发布流程

每次发布都用同一份说明大纲，结构、语气与篇幅保持一致。

## 说明大纲

```
与 <上一个版本> 相比的变化。

## 新增
- 一句话一条，用户能看到的新能力

## 修复
- 一句话一条，用户能感知到的行为变化

## 兼容
- 旧版配置能否沿用
- 安装包文件名与校验文件
```

- 只写与上一个版本的差异，以及用户能观察到什么；不写内部实现、不解释「以前为什么错」、不列内部键名与文件清单。
- 需要时增加 `## 移除`；没有内容的小节直接省略；不新增其他小节。
- 每节 2–5 条，每条一句、不换行续写；全文约 15 行以内。
- 不写包体积、压缩测试、构建耗时、工作流步骤等过程数据。
- 用中文写；版本号、文件名、命令与设置键保持原样。

## 步骤

1. 改版本：`package.json` 的 `version`（唯一来源，关于页与更新检查都读它）。
2. 写说明：`docs/release-notes/v<版本>.md`，按上面的大纲。
3. 提交并打附注标签：`git tag -a v<版本> -m '<说明首行>'`（推 master 与标签一起推）。
4. 工作流 `.github/workflows/release.yml` 按标签打包、生成 `SHA256SUMS.txt` 并建 Release（说明为自动生成）。
5. 覆盖说明：`gh release edit v<版本> --notes-file docs/release-notes/v<版本>.md`。
