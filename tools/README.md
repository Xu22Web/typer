# Typer 文件接收端脚本

把**任意文件**从一台机器"打"到另一台机器（终端、串口、KVM、远程桌面里的接收端）：逐片校验、
断点续传、合并后校验整文件完整性。

接收端是**零依赖**的单文件 Node ESM：只用 `node:` 内置模块，**不需要 `npm install`**，
**Node ≥ 16** 即可运行（`node typer-recv.mjs --selftest` 可先自检环境）。

```bash
node typer-recv.mjs --help        # 查看全部选项
node typer-recv.mjs --selftest    # 校验 CRC / 编码 / 转义 / 片号解析是否正常
```

> 本目录里的 `.mjs` 与 `run.bat` 是**构建产物**（源码 `typer-recv.ts`，由 `pnpm build:tools` 用
> esbuild 打成压缩过的单文件，并生成双击入口 `run.bat`）。发到目标机时请保留 `.mjs` 扩展名：
> Node 靠扩展名识别 ESM，改名成 `.js` 后需要同目录有 `{"type":"module"}` 的 `package.json` 才能运行。

## 1. 怎么把脚本弄到目标机

| 方式                 | 做法                                                                                                                                         |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **让 Typer 打进去**  | 文件页脚本卡点「插入接收脚本到文本输入」→ 内容区变成脚本全文并切到文本模式 → 在目标机执行 `cat > typer-recv.mjs` 再开始输入，最后按 `Ctrl+D` |
| **导出文件**         | 文件页/设置页的「导出脚本」把 `typer-recv.mjs`、`run.bat` 与本文档复制到指定目录（双击 `run.bat` 即可运行）                                  |
| **从安装目录直接取** | 安装后的 `<安装目录>\resources\tools\`（脚本、`run.bat` 与本文档都在，“打开脚本目录”按钮可直接定位）                                         |

`run.bat` 是给人用的入口：双击即可运行接收端（等价于 `node typer-recv.mjs`，命令行参数原样转发、
退出码原样返回），不必手敲命令；PATH 上没有 Node 时会给出提示并停住窗口。它由 `pnpm build:tools`
随脚本一起生成。

## 2. 为什么不是"直接输入二进制"

| 问题     | 说明                                                                                     |
| -------- | ---------------------------------------------------------------------------------------- |
| 控制字符 | `\0` 无法输入；`\n` 是"回车提交"；`\t` 是 Tab 键；`\x1a`(Ctrl+Z) 在 Windows 控制台是 EOF |
| 终端行为 | 行缓冲有行宽上限、可能回显、启用 bracketed paste 会插入 `ESC[200~`                       |
| 链路质量 | 串口/远控会丢字符或重复字符，且没有重传机制                                              |

所以数据先编码成**纯 ASCII 的安全字符集**，切成**每片一行**的帧；每片自带 CRC32 + SHA-256 前缀，
接收端逐片校验、失败只重传该片，最后合并并校验整文件哈希。

## 3. 编码怎么选

| 编码            | 体积          | 适用                                                                            |
| --------------- | ------------- | ------------------------------------------------------------------------------- |
| `gzb64`（默认） | 通常 0.3~0.5× | 文本 / 代码 / JSON 的默认选择：逐片 deflate 后 Base64；已压缩的包也略优于 `b64` |
| `b64`           | 1.34×         | 目标端可靠时的紧凑选择（含大小写与 `+ / =`），任何版本的接收端都能解            |
| `hex`           | 2×            | **任何文件**（二进制、GBK、EXE…）。只有 `0-9A-F`，最抗终端与输入法干扰          |
| `txt`           | 近似 1×       | 纯 UTF-8 文本，可读性最好（`空格`/`CR`/`LF`/`TAB` 转义成 `\s`/`\r`/`\n`/`\t`）  |

需要**逐字节还原**（例如 GBK 文件）时用 `gzb64` / `b64` / `hex`：它们传的就是文件原始字节，
与编码、locale、终端代码页都无关。`txt` 仅接受合法 UTF-8（带 BOM 会被拒绝），
因为只有"文件字节 == 该文本的 UTF-8 编码"时，两端的整文件哈希才一致。

`gzb64` 是 1.x 之后新增的编码：目标机上那份**旧版** `typer-recv.mjs` 会明确报「不支持的编码」并拒绝该片，
不会写出坏数据；换上新脚本即可。与旧脚本配合时选 `b64` 或 `hex`。

在 Typer 里编码、片大小、帧长上限都在「设置 → 文件传输」中调整；文件模式**不受节奏与随机性设置影响**
（数据传输要的是"一个字符都不丢"：帧内每个字符单独投递并留 1ms 间隔，实测 2.7 万字符零丢失、
约 450 字符/秒；一次投递多个字符或零延迟快投都会让终端静默丢字符）。传输组自己的「片间断顿」
只在稳健档生效，极速档固定为 0。

## 4. 线格式 v1（收发双方唯一契约）

每帧**一行、纯 ASCII、无空白**：

```
开始帧  @TYPER1/B <job> <total> <size> <enc> <chunk> <nameB64> <sha256>
数据帧  @TYPER1/D <job> <seq> <total> <bytes> <crc32> <sha16> <enc> <payload>
结束帧  @TYPER1/E <job> <total> <size> <sha256>
续传令  @TYPER1/R <job> <total> <missing>
```

| 字段            | 含义                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------ |
| `job`           | 任务标识（8 位小写 hex）。接收端用它隔离工作目录，避免两次任务互相污染                           |
| `seq` / `total` | 0 基片号 / 总片数                                                                                |
| `size`          | 原始文件字节数（`gzb64` 也始终是解压后的大小，整文件哈希按它复核）                               |
| `bytes`         | 本片**线上**字节数（`hex`/`b64` 为定长切片，末片可小；`gzb64` 是压缩后长度；`txt` 为文本字节数） |
| `crc32`         | 本片线上字节的 CRC32（8 位小写 hex）                                                             |
| `sha16`         | `SHA-256(本片线上字节)` 的前 8 字节（16 位小写 hex）                                             |
| `enc`           | `hex` / `b64` / `txt` / `gzb64`                                                                  |
| `payload`       | 编码后的数据（不含任何空白字符）                                                                 |
| `nameB64`       | 文件名的 UTF-8 base64url（`-` 表示不指定）                                                       |
| `sha256`        | 整文件 SHA-256（64 位小写 hex）                                                                  |
| `missing`       | 缺失片号，逗号分隔，支持 `a-b` 区间（`-` 表示无缺失）                                            |

**回执**（接收端输出，`#` 前缀）：`#BEGIN` / `#RESUME` / `#OK` / `#SKIP` / `#FAIL` / `#MISS` / `#DONE` / `#BAD`。

**退出码**：`0` 成功且校验通过；`2` 数据不全；`3` 完整性校验失败；`4` 参数或 IO 错误。

线格式的**唯一实现**在 `src/main/util/frame.ts`：Typer 主进程（生成帧、算续传计划）与接收端脚本
（解析帧、逐片校验、合并）引用同一份代码，收发两端不会出现实现漂移。

## 5. 选项

```
node typer-recv.mjs [选项]
  -o, --out <path>        输出文件（默认 <分片目录>/<开始帧里的文件名>，无名字则 job-<id>.bin）
  -d, --dir <path>        分片工作目录（默认 ./.typer-<job>）
      --in <file>         从文件读取帧（默认读标准输入）
      --cooked            强制行缓冲读入（TTY 下默认 raw：不回显、无行宽限制）
      --no-resume         忽略已有分片全部重收（默认：校验通过即跳过）
      --no-overwrite      输出文件已存在时拒绝覆盖（默认直接覆盖）
      --report <path>     续传报告 JSON（默认 <dir>/resume.json；`-` 表示关闭）
      --token             数据不全时额外打印可回填 Typer 的续传令牌
      --ack <target>      回执输出到 stdout | stderr | none（默认 stdout）
      --progress-every <n> 每 n 片打印一次 #OK（0 = 只打印失败）
      --keep-parts        合并成功后保留分片（默认只留结果文件）
      --charset <cs>      txt 编码的写盘编码（默认 utf-8）
  -q, --quiet             只在失败 / 摘要 / 结果时输出
  -v, --verbose           额外诊断信息
      --selftest          环境自检后退出
```

不指定 `-o` 时，结果按**开始帧里的原始文件名**写进分片目录（`-d`，默认 `./.typer-<job>`）：
校验通过后先原子替换成结果文件，再清掉分片与续传报告，所以该目录最后只剩一个结果文件。
同名已存在时默认直接覆盖，加 `--no-overwrite` 可以改成拒绝覆盖。

### 典型流程

```bash
# ① 目标机：启动接收端，等待输入（raw 模式，被"打"进来的内容不会回显）
#    导出目录下双击 run.bat 等价于下面这行
node typer-recv.mjs -o received.bin --token

# ② 发送端：Typer 的「文件」页选择文件 → 开始输入

# ③ 中途失败 / 被打断：目标机会打印
#    #MISS 12-20
#    @TYPER1/R a1b2c3d4 69 12-20
#    把片号或续传令牌填回 Typer 的「只发指定片」/「续传状态」，只补这几片

# ④ 全部通过时：#DONE <路径> <字节数> <sha256>，退出码 0
#    结果就写在分片目录里，用开始帧带过来的原始文件名（见上）
```

### 场景要点

- **终端（Windows Terminal / conhost / bash）**：直接运行即可，TTY 下自动进 raw 模式（无回显、无行宽限制）。
- **串口 / 环回链路**：回执会顺着链路回到发送端，可能被对端当成键盘输入 →
  用 `--ack none`（或 `stderr`）关闭回执，靠退出码与 `--report` 判断结果；同时建议减小片、放慢节奏。
- **目标端没有 Node**：用 `--in frames.txt` 从文件读帧，或把帧文本打进任意文件后拷到有 Node 的机器上离线合并。

## 6. 开发

```bash
pnpm build:tools    # tools/typer-recv.ts → tools/typer-recv.mjs（压缩）+ tools/run.bat
pnpm test:system    # 先构建，再用真实子进程跑接收端做端到端验证
```

改动 `src/main/util/frame.ts`（线格式）或 `tools/typer-recv.ts`（接收端）后都要重新构建。
接收端代码必须留在 **Node 16 可用的 API 范围**内：`scripts/build-tools.mjs` 在构建后会扫描
`structuredClone`、`Array#at` 等不可用 API，命中即构建失败。

产物是**压缩过**的单文件（约 24 KB）：它会被 Typer 当作文本"打"进目标终端，
体积直接决定在串口 / 远控这类只能逐字符输入的链路上要花多久，所以不开 sourcemap、
不保留注释，未用到的线格式函数也会被 tree-shake 掉。
